# FileCopy 开发需求

## 1. 背景

通过远程桌面连接到海外的电脑时，用 RDP 拖拽传文件非常慢，要等很久。

需要一个**简单、轻量**的应用：两台电脑各装一个客户端，连同一台服务器，文件经服务器中转，以此代替 RDP 拖拽，高效传输文件。

使用体验参考 OneDrive / Nextcloud：可以管理文件夹、上传下载文件，并且有 **"始终保留在此设备上"** 和 **"释放空间"** 两个功能。

## 2. 总体要求

- **越轻量越好**：只是一个简单的 app，不追求大而全
- **服务端**：部署在 Linux 服务器上，使用 Go（单个静态二进制，仅用标准库）
- **客户端**：Windows 10，C# WPF 图形界面
- **认证**：单个访问 Token，不做多用户
- **传输快**：针对高延迟的跨洋链路优化

## 3. 关键决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 服务端语言 | Go | 编译成单个约 7 MB 的静态二进制，部署简单，无依赖 |
| 服务端环境 | Linux + 单 Token | 最轻量 |
| "保留 / 释放空间" 的实现方式 | **仅在 WPF 程序内实现** | 最初做了资源管理器原生集成（Windows Cloud Files API，与 OneDrive 相同机制），已经跑通，但用户认为"这样还不如直接装 OneDrive"，改为在程序界面里实现。cfapi 相关代码已全部删除 |
| 文件列表界面风格 | 参考资源管理器 + OneDrive | 用户习惯，看起来像原生的文件管理器 |
| 操作入口 | 右键菜单（不放操作按钮列） | 与 OneDrive 一致 |
| 控制面板形式 | 服务端内置网页 `/admin`（`embed`，仍只用标准库），与客户端同端口、公网可访问 | 不用另装程序，浏览器即可管理；靠管理密码 + TOTP + 失败锁定保护 |
| 设备区分 | 用客户端设置里的设备 ID（EquipmentId），必填；面板可在线改名并同步到客户端 | 已有字段，备份包也按它命名；不做多用户 |
| 断开连接 | 全局开关，关闭后所有客户端请求返回 503 并切断进行中的传输，重启后保持 | 管理员一键停服，面板本身不受影响 |
| TOTP 的作用范围 | 面板登录 + 客户端从托盘重新打开时解锁（解锁后 5 分钟内免验证） | 防止陌生人在已登录的电脑上操作；密钥只存服务端，离线无法解锁 |
| 只读文件夹 | 对所有客户端生效，面板不受限；本地修改恢复为云端版本 | 指定内容只允许下载，禁止任何编辑 |

## 4. 服务端需求

### 4.1 功能

- 列出全部文件和文件夹（递归，含大小、修改时间）
- 下载文件，支持 HTTP `Range`（断点续传、多连接分块下载）
- 分块上传：先初始化会话，再并行、乱序上传分块，最后确认完成；分块可重试
- 删除、重命名 / 移动、新建文件夹
- **冲突保护**：上传完成时，如果服务器上的文件在客户端上次同步后被别人改过，把旧版本另存为 `name (conflict 时间).ext`，不直接覆盖

### 4.2 安全

- 所有接口都要求 `Authorization: Bearer <token>`，Token 使用常量时间比较
- Token 长度至少 16 个字符
- 路径安全：所有路径限制在数据目录内，不能用 `../` 越界；内部的上传临时目录 `.uploads` 对外不可见
- 支持直接配置 TLS 证书，或在前面加 Caddy / Nginx 提供 HTTPS

### 4.3 运维

- JSON 配置文件：监听地址、数据目录、Token、TLS 证书（可选）
- 提供 systemd 服务示例
- 自动清理超过 24 小时的未完成上传

### 4.4 控制面板（`/admin`）

- 登录：管理密码（config 中的 `adminPassword`，未设置则用 Token；可在面板修改，哈希存入状态文件）+ TOTP 验证码（启用时）；同一 IP 连续失败 5 次锁定 5 分钟；会话 12 小时，Cookie `HttpOnly`、`SameSite=Strict`，修改类请求要求 `X-Requested-With` 头
- 连接：全局 "允许连接" 开关；设备列表（设备 ID、IP、最后活动、在线、实时速度、累计流量、统计起始时间），可重置流量、在线修改设备 ID（客户端下次 ping 时同步，确认前显示 "待同步"）、删除记录；同一 ID 同时来自多个 IP 时标红；显示数据 / 回收站占用和磁盘剩余空间
- 文件：上传（分块协议同客户端，同时 3 个文件）、下载（单个文件直接下载；文件夹或多选时由 `GET /admin/api/fs/zip?path=…` 流式打包成 zip，不压缩）、新建、重命名、复制、移动、删除、设为只读 / 取消只读；当前页面和文件夹记在 URL hash 中
- 回收站：客户端和面板的删除都进入 `.filecopy/trash/`，可还原（原位置被占用时改名）、永久删除（均可多选）、清空；超过 30 天自动清理
- 界面：左侧导航，页面内对话框与提示，跟随系统深色模式；不依赖任何前端库
- 安全：启用 / 停用 TOTP（二维码由服务端生成）、修改管理密码（修改后其他会话退出）
- 状态持久化在 `.filecopy/state.json`（Docker 下 config.json 只读挂载）；`.filecopy` 与 `.uploads` 一样对客户端不可见

## 5. 客户端需求

### 5.1 连接与设置

- 设置项：服务器地址、Token、本地保留文件夹、设备 ID（必填，每个请求以 `X-Equipment-Id` 发送；面板改名后自动更新）、开机自动连接
- 服务端启用 TOTP 时，启动客户端、窗口关闭到托盘后再次打开（含托盘 "打开同步文件夹"）需输入验证码，由服务器校验；解锁后 5 分钟内免验证；无法校验（连不上服务器、Token 被拒绝）时可选择清除 Token 和该服务器的保留状态并打开设置，没有 Token 即不再锁定
- 只读文件夹：显示 🔒，禁用上传 / 新建 / 重命名 / 删除；本地修改的保留文件恢复为云端版本（修改版移到回收站），本地新建的文件移到回收站
- 本地保留文件夹默认 `文档\FileCopy\data`（`%USERPROFILE%\Documents\FileCopy\data`），可在设置中修改
- `文档\FileCopy` 下只放程序 `app` 和本地保留文件夹 `data`（备份在 `data\backup`）；设置 `settings.json`、保留状态 `state-*.json`、日志 `log.txt` 放在 `%AppData%\FileCopy`，避免被 OneDrive 同步
- Token 用 DPAPI 加密保存，不明文落盘
- 首次运行（还没有设置）时自动打开设置窗口

### 5.2 文件浏览（资源管理器风格）

- 列顺序：**名称 | 状态 | 修改日期 | 类型 | 大小**
- 使用系统的文件图标和类型名称（如 "7Z 文件"），与资源管理器一致
- 大小按资源管理器的格式显示：整 KB、向上取整、带千位分隔符，如 `146,105 KB`；文件夹不显示大小
- 日期格式：`2026/10/22 19:45`
- 行样式：悬停浅蓝、选中蓝底带边框、无表格线、无多余的横向滚动条
- 路径导航条（可点击跳转）、"上级" 按钮
- 双击文件夹进入；双击文件打开（未下载的先下载再打开）
- 支持多选
- 快捷键：`Enter` 打开、`Backspace` 返回上级、`F2` 重命名、`Delete` 删除、`F5` 刷新

### 5.3 状态图标（OneDrive 风格）

| 图标 | 状态 | 含义 |
|---|---|---|
| 实心绿色 ✔ | 始终在此设备上可用 | 用户选择了 "始终保留在此设备上" |
| 空心绿色 ✔ | 在此设备上可用 | 双击打开时下载的，没有固定保留 |
| 蓝色 ☁ | 联机时可用 | 仅在云端，不占本机空间 |
| 蓝色 ⟳ | 正在同步 | 正在传输，或等待上传 / 下载 |

### 5.4 始终保留在此设备上 / 释放空间

- **始终保留在此设备上**：把文件下载到本地保留文件夹，并保持双向同步
  - 对文件夹设置后，文件夹里的全部文件都下载；以后服务器上新加进这个文件夹的文件也自动下载
  - 右键菜单中该项显示勾选状态；再次点击取消勾选：本机副本保留，但不再固定（变为空心绿勾）
- **释放空间**：删除本机副本，文件仍显示在列表中（蓝色云朵），服务器上的文件不受影响
  - 如果本机有尚未上传的修改，先弹窗确认
  - 仅存在于本地、还没上传的文件不会被删除
  - 对 "保留的文件夹" 里的单个文件释放空间时，文件夹不再整体保留，但其中其他已下载的文件继续保持固定

### 5.5 同步规则

不做定时自动同步；只在启动（连接成功）、点击 "刷新" / F5 / 托盘 "立即同步"、点击 "备份" 时同步，新建 / 重命名 / 删除 / 上传操作完成后也会刷新一次以更新列表。

上传过程中如果本地文件被修改（大小或修改时间变化），放弃该次上传，避免服务器收到新旧混合的内容；因此一直被其他程序写入的文件不会上传，等写入停止后的下一次刷新再上传。

| 情况 | 处理 |
|---|---|
| 本机修改、服务器未变 | 自动上传 |
| 服务器修改、本机未变 | 自动下载更新 |
| 两边都修改 | 上传本机版本，服务器上的旧版本另存为冲突副本 |
| 本地保留文件夹里新增的文件 | 自动上传 |
| 服务器上删除了已保留的文件 | 本机副本移到**回收站**（可恢复） |
| 保留的文件夹里服务器新增了文件 | 自动下载 |

### 5.6 文件操作

- 上传文件、上传文件夹（按钮选择）
- **从资源管理器拖拽**文件 / 文件夹到窗口上传；拖到某个文件夹行上则上传到该文件夹
- 从外部上传的文件默认只在云端；若目标文件夹是保留的，同时在本地放一份副本，避免重复下载
- 新建文件夹、重命名、删除（服务器删除，本机副本进回收站，删除前确认）
- 下载到...：保存到任意位置，不计入 "保留"
- 打开本地保留文件夹

### 5.7 传输

- 每个文件切成 4 MB 分块，4 条连接并行；同时最多传 3 个文件
- 分块失败自动重试（最多 4 次，递增等待）
- 下载先写入 `.fcpart` 临时文件，完成后再替换，并设置为服务器上的修改时间
- 传输列表显示：方向、文件、大小、进度条、速度、状态

### 5.8 其他

- 关闭窗口时最小化到系统托盘；托盘菜单：打开、打开同步文件夹、立即同步、退出
- 只允许运行一个实例
- 日志同时显示在界面并写入 `%AppData%\FileCopy\log.txt`，超过 5 MB 时转存为 `log.1.txt`（只保留一份）
- 界面底部状态栏：连接状态、本地保留文件夹、本机已保留文件数量和总大小

### 5.9 一键备份

- 工具栏 "备份" 按钮：把 `D:\Config`、`D:\Recipes`、`D:\MechanicalParameters`（固定）压缩成一个 7z 包
- 包名为设置中的 **设备 ID**（EquipmentID），用来区分不同电脑，如 `backup/XZT1-CB.7z`、`backup/XZT1-DB1.7z`
- 本机保存在 `<本地保留文件夹>\backup\<设备 ID>.7z`，同时上传到服务器 `backup/`，作为保留文件同步
- 同名覆盖，只保留最新；先压缩为同目录下的临时文件（`.tmp.fcpart`），完成后再替换；7-Zip 报错（退出码 ≥ 2）时不影响上一份备份，仅有部分文件读取失败（退出码 1）时仍会替换
- 上一份备份仍在传输时不允许再次备份；上传过程中本地文件被替换时放弃该次上传，避免服务器收到新旧混合的文件
- 不存在的源文件夹跳过；被占用无法读取的文件跳过并在日志中列出
- 未连接服务器时只保存在本机，连接后自动上传
- 依赖 7-Zip：安装版 `7z.exe`，或放在程序目录的 `7za.exe`

## 6. 不做的内容

- 资源管理器集成（占位符文件、导航栏入口、资源管理器右键菜单）——已明确放弃
- 多用户 / 多账号
- 文件版本历史（只保留冲突副本；同步覆盖的旧版本不进回收站）
- 分享链接、面向普通用户的网页端（网页只有管理用的控制面板，只针对电脑浏览器设计）
- 控制面板操作日志
- 跨程序重启的上传断点续传（上传会话只存在服务端内存中，重启后重新上传；分块级别的失败会自动重试）
